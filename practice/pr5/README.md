# ПР5. Оптимизация репликации

**Ветка:** `feature/replication-optimization`. Документы: `docs/Replication_Baseline.md`, `docs/Replication_Optimization.md`.

## Адаптация
50+ «реплицируемых акторов» = друзья-боты. Нагрузка: `NOMI_BOTS=50`. Профилировщик Unreal заменён счётчиками сервера `GET /stats` (`bytesOut`, `pktOut`, `skipped`).

| Приём из задания | В Nomi (`server.relay`) |
|---|---|
| Replication Graph, релевантность | друзья дальше 5 км не отправляются (`RADIUS`) |
| Net Dormancy | друг, сдвинувшийся < 3 м с последней отправки, «спит» (`MIN_MOVE`) |
| Push-based / delta | отправляется только при изменении |
| Квантование | координаты `int32 × 10⁷` (9 байт вместо 17 при `float64`) |
| NetUpdateFrequency | тик ботов 5 Гц, а клиентам уходит не чаще изменения |

## Измерение
```bash
NOMI_OPT=0 NOMI_BOTS=50 npm start   # baseline
NOMI_OPT=1 NOMI_BOTS=50 npm start   # оптимизировано
# откройте клиент, подождите, затем дважды с интервалом 30 с:
curl localhost:3000/stats           # (bytesOut2 - bytesOut1) / 30 = байт/с
```
Одинаковые условия: 1–2 клиента, 30 с, один и тот же сценарий. Заполните таблицу «до/после» (KB/s, пакетов/с, акторов). Ориентир: снижение на 40–60%.

## Объяснение для жанра
Друзья на карте двигаются медленно, а большинство стоит: dormancy и порог 3 м убирают почти весь трафик, радиус убирает далёких.

## Защита
- **Почему квантование безопасно?** 10⁻⁷° ≈ 1 см, точнее GPS.
- **Риск dormancy?** Друг «застывает» до сдвига на порог; порог выбран ниже погрешности GPS.
