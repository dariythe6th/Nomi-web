# ПР6. Шифрование и защита от DDoS

**Ветка:** `feature/encryption`. Документы: `docs/Security.md`, `docs/Cloudflare_Spectrum_Setup.md`.

## Реализация (`shared/crypto.mjs`)
- `KEY_EXCHANGE` (открытый): клиент и сервер обмениваются публичными ключами **ECDH P-256** (в браузере X25519 в WebCrypto пока не универсален).
- Ключ: **HKDF-SHA256** (`info = "nomi-v1"`), шифр: **AES-256-GCM**.
- `ENCRYPTED`: `[заголовок открытый = AAD][nonce 12 Б][шифртекст + tag 16 Б]`. Заголовок читается до расшифровки, но подменить его нельзя.
- Nonce = направление (4 Б: 1 клиент, 2 сервер) + растущий счётчик (8 Б): пара «ключ + nonce» не повторяется, `rand()` не используется.
- Ошибка тега → пакет молча отбрасывается, `AUTH_FAIL <ip>` в логе (`cf-connecting-ip`, если за Cloudflare).
- Сессионный ключ на соединение (WebSocket), поэтому таблица по адресам не нужна.

## Wireshark и негативный тест
1. Loopback (Npcap на Windows), порт 3000, фильтр `websocket`: «до» читаемый JSON/байты, «после» случайные байты (приложение шифрует и без TLS).
2. Негативный тест: прокси-скрипт меняет 1 байт шифртекста → `AUTH_FAIL`, `/stats.authFail` растёт. Тест `npm test` проверяет то же.

## Cloudflare
Для веб-приложения достаточно проксирования (оранжевое облако) с WebSocket; **Spectrum** (TCP/UDP-прокси) обычно требует платный план, уточните у преподавателя и приложите скриншоты того, что используете.
1. Origin закрыть: на файрволе VM пускать порт только с [диапазонов IP Cloudflare](https://www.cloudflare.com/ips/).
2. Домен на Cloudflare → DNS-запись `nomi.example.com` с проксированием → клиент ходит по `wss://`.
3. WAF/Rate limiting на `/upload`, DDoS Managed Ruleset (чувствительность укажите и обоснуйте).
4. Сервер видит IP Cloudflare, реальный IP берётся из `CF-Connecting-IP` (бан по IP делайте по нему, не по адресу сокета).

## Ограничения (опишите в Security.md)
Голый ECDH уязвим к MITM: злоумышленник подставит свои ключи. Исправление: подписать ключ сервера (сертификат/закрепление ключа) и использовать TLS (`wss`). Нет защиты от повтора пакетов (можно проверять монотонность счётчика). `/upload` без аутентификации.

## Защита
- **Почему нельзя `rand()` в nonce?** Повтор nonce в GCM раскрывает данные и ключ аутентификации.
- **Зачем закрывать origin?** Иначе атакующий обойдёт прокси, зная IP.
